# 18. 확장 지점 · 품질 검증

> 옵션은 새로 만드는 게 아니라 필수 설계의 확장 지점에 꽂는다

## 필수 설계가 가진 확장 지점

| 확장 지점 (필수 설계) | 가능해지는 옵션 |
|---|---|
| 상태 변화마다 이벤트 발행 (Outbox) | O1 실시간: 구독만 추가 |
| 노드는 논리 모델만 안다 | O2 모델 교체: Gateway 설정만 변경 |
| Registry에 Mock Tool 등록 가능, Trace 기록 | O3 품질 검증: 시뮬레이션 · 회귀 평가 |
| Compiler가 독립 서비스 | O4 동적 계획: Planner가 같은 Compiler 호출 |
| 중단 · 재개 공통 모듈 | O4 자식 Run 대기, O1 동기→비동기 전환 |
| Agent 실행기의 컨텍스트 구성 단계 분리 | O5 기억: Recall만 끼움 |

## 옵션별 터치 크기

| 옵션 | 터치 유형 | 새로 더하는 것 | 답안 분량 |
|---|---|---|---|
| O1 실시간 | 박스 추가 | SSE gateway, 진행 이벤트 | 구성도 박스 + 짧은 설명 |
| O2 모델 교체 | 기존 확장 | 폴백 체인 설정 | 표 하나 |
| O3 품질 검증 | 기존 확장 | 시뮬레이션 모드, 골든셋 | 한두 줄 |
| O4 동적 계획 | 새 노드 유형 | Planner, 자식 Run | 메커니즘 1장 |
| O5 기억 · 지식 | 박스 추가 + 확장 | Memory service | 메커니즘 1장 |

## [옵션 O3] 품질 사전 검증
- **시뮬레이션 실행**: Registry의 Mock Tool로 외부 부작용 없이 새 버전 실행
- **골든셋 회귀 평가**: HITL 반려 · 낮은 평가 건을 골든셋으로 수집 → 프롬프트 · 모델 · 워크플로 변경 시 비교
- **카나리 배포**: 새 IR 버전을 일부 Run에만 → 지표 비교 후 전환
- Trace에 프롬프트 버전 · 모델 · graph_hash가 남아 있어 원인 분리 가능

## 답안 활용
요구사항에 옵션이 없어도 마지막 "확장 방향" 장표로:
"본 설계는 이벤트 발행, 논리 모델, 컴파일러 서비스화, 중단 · 재개 모듈, 컨텍스트 구성 분리라는 확장 지점을 갖고 있어, 실시간 진행 확인 · 모델 교체 · 동적 계획 · 장기 기억을 구조 변경 없이 수용한다."
