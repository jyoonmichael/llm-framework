범위 제외: 부서 · 업무 단위 관리(멀티테넌시, 부서별 비용 집계)

## 해석 포인트
- R11: 인프라 장애(Worker 사망) vs 논리적 실패(Agent 포기, 모델 장애)
- R7: 실행 중 통제(루프 · 토큰) vs 권한 통제(최소 권한 · 승인)
- R9: 기록 재생(같은 결과 보기) vs fork 재실행(다시 돌려보기)
- R2 vs R12: 병렬을 **정의**할 수 있나(R2) vs 실제로 **얼마나 동시에** 돌리나(R12)

## 뿌리 메커니즘 (실제로 깊게 익힐 것)

| 뿌리 | 해당 요구사항 |
|---|---|
| 중단 · 재개 (Checkpoint + Outbox) | R6, R9, R11, O1, O4 |
| Agent 통제 (실행기 검사 지점) | R7, R10, O5 |
| DSL → IR (Compiler + Policy) | R4, R5, O4 |
| 공유 State · 이벤트 기반 스케줄링 | R1, R2, R8, R12 |

## 연습 우선순위
1. 필수 + 어려움: R11, R12 (장애 인계 시퀀스, 장애 매트릭스, Map 노드)
2. 옵션 + 어려움: O4, O5
3. 필수 + 보통: R5~R10 (기본 장표 위에서 말로 풀 수 있게)

## 정합성 검증

요구사항끼리 부딪힐 수 있는 지점을 모두 점검하고, 어떤 장치로 해소되는지 정리했다.

| 맞물리는 요구사항 | 잠재 충돌 | 해소 방법 | 근거 불변식 |
|---|---|---|---|
| O4 동적 계획 ↔ R4 버전 무영향 | 실행 중 그래프를 바꾸면 버전 고정이 깨짐 | 부모 그래프 불변, 새 계획은 자식 Run (생성 IR도 IR store에 저장) | I1, I7 |
| O4 동적 계획 ↔ R7 · R10 통제 · 보안 | Agent가 위험한 계획 생성 | 같은 Compiler 검증, 자식 권한 · 예산 ⊆ 부모, 쓰기 Tool엔 승인 자동 삽입 | I7, I8, I9 |
| O4 동적 계획 ↔ R11 장애 재개 | 자식 실행 중 장애 | 자식도 일반 Run이라 동일 재개 메커니즘, 부모는 Suspended로 안전 대기 | I1, I2 |
| O4 동적 계획 ↔ Run 취소 | 부모 취소 시 자식 고아화 | **부모 취소 시 자식 연쇄 취소** (parent_run_id 기준) | I1 |
| O5 기억 ↔ R9 재현 | 기억 저장소가 바뀌어 재생 결과가 달라짐 | 조회한 기억 ID · 내용을 반복 기록에 저장, 재생 시 재사용 | I6 |
| O5 기억 ↔ R10 보안 | 기억에 민감정보 · 악성 지시 축적 | 저장 전 마스킹 · 품질 게이트, 주입 시 데이터 딱지(인젝션 격리) | I5 |
| O5 기억 ↔ R11 장애 | 실패한 중간 판단이 기억으로 저장 | 기억 쓰기는 Run 완료 후에만, 성공 · 승인 건 위주 | I3 |
| O1 실시간 ↔ R6 장기 대기 | 사용자가 오래 기다림 | 동기 대기 후 비동기 전환, SSE로 상태 확인 | I2 |
| O1 실시간 ↔ R10 보안 | 진행 이벤트로 민감정보 노출 | 진행 이벤트에도 마스킹, 구독 시 Run 조회 권한 확인 | I5 |
| O1 실시간 ↔ R11 장애 | 재연결 시 이벤트 유실 | 상태 이벤트는 Outbox · Event log에서 재생, 진행 이벤트는 유실 허용 | I3 |
| O2 모델 교체 ↔ R9 재현 | 폴백 모델이 다른 결과 생성 | 실제 모델 · 강등 여부 기록(비투명 폴백), 재생은 기록값 사용 | I6 |
| O2 모델 교체 ↔ R10 보안 | 폴백으로 보안 등급 우회 | 데이터 등급 필터는 폴백 시에도 유지, 안전 거부는 폴백 금지 | I5, I9 |
| R2 · R12 병렬 ↔ R7 토큰 예산 | 동시 호출이 예산을 초과 | 예약 · 정산 방식의 원자적 차감 | I8 |
| R2 · R12 병렬 ↔ State 정합성 | 병렬 노드의 같은 필드 쓰기 충돌 | Map은 항목별 슬롯, 고정 분기는 reducer 선언 (없으면 Validator가 금지) | I2, I7 |
| R11 장애 재개 ↔ R7 토큰 예산 | 재생 시 비용 중복 청구 | 재생 구간은 기록값 사용 → 재청구 없음, 미정산 예약은 임대 만료 시 해제 | I6 |
| R6 HITL ↔ R7 토큰 예산 | 대기 중 예약이 묶임 | 중단(Suspended) 시점에 미정산 예약 해제 | I3 |
| R6 HITL ↔ R4 버전 | 대기 중 새 버전 배포 | 대기 Run은 시작 버전 유지, 이전은 안전 지점에서 graph_hash 호환 시 명시적으로만 | I1 |
| R6 HITL ↔ R11 장애 | 승인 요청 중복 · 유실 | Outbox로 유실 방지, HITL 서비스는 요청 ID로 중복 제거, 재개 토큰 1회용 | I3, I4 |
| R5 노코드 ↔ R10 보안 | 현업이 보안 설정 누락 | Policy 강제 규칙을 컴파일 시 주입 | I9 |
| R8 멀티 Agent ↔ R7 통제 | Agent 간 무한 핑퐁 | 종료 조건은 코드(Router)가 판단, 반복 · 예산 상한 | I8 |

### 검증 중 보완한 항목
1. 부모 Run 취소 시 자식 Run 연쇄 취소 (06 Run manager에 반영)
2. HITL 중단 시 미정산 토큰 예약 해제 (12에 반영)
3. Map 항목의 펜싱 토큰 · 멱등키 · dedupe 키에 항목 번호 포함 (10, 11에 반영)
4. SSE 구독 시 Run 조회 권한 확인, 진행 이벤트 마스킹 (15에 반영)
5. "조직 정책"을 "공통 정책(Policy)"으로 명칭 변경, 테넌트 · 부서 관련 항목 제거
6. 실행기 종료 상태를 문서와 코드에서 동일한 7종으로 통일 (08, 19에 반영)
